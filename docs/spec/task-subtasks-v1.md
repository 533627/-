# 任务拆分与逐项完成规格

## 目标

运营组长或其他有派单权限的管理者可以创建一个带执行时间段的主任务，并在主任务内添加 1 至 20 个小任务。主任务负责人逐项确认完成；最后一个小任务完成时，主任务自动完成。

## 已确认假设

- 一个主任务只有一名负责人，所有小任务由该负责人执行。
- 主任务使用开始时间和结束时间表示执行周期。
- 每个小任务包含标题，可选说明，不单独指定负责人或截止时间。
- 没有小任务的旧任务继续沿用原有“确认完成”流程。
- 已创建的小任务本阶段不支持删除或改名，避免破坏完成审计。

## 接口与权限

- 创建主任务时，服务端接收 `startsAt`、`dueAt` 和 `subtasks[]`。
- `subtasks` 至少 1 条、最多 20 条；标题 1 至 200 字，说明最多 1000 字。
- 只有主任务负责人可以确认小任务完成。
- 小任务完成操作幂等；重复点击不会重复写入完成记录。
- 有小任务的主任务不能通过原有“确认完成”按钮提前结束。
- 最后一个小任务完成时，在同一数据库事务内自动完成主任务。

## 页面行为

- 发布任务表单提供开始时间、结束时间和“小任务清单”。
- 默认显示一条小任务，可继续添加或移除未发布的小任务。
- 任务卡片展示执行周期、完成进度和小任务列表。
- 负责人在每个未完成小任务旁点击“确认完成”；其他账号只读。
- 全部完成后显示主任务已完成。

## 技术与验证

- 技术栈：Next.js、React、Prisma、PostgreSQL、Vitest、Playwright。
- 测试：数据库集成测试覆盖创建、越权、幂等和自动完成；浏览器测试覆盖动态添加与逐项完成。
- 命令：`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`。

## 成功标准

- 一次发布可以保存多条小任务。
- 员工能够逐条确认，刷新后状态仍保存。
- 非负责人无法完成小任务。
- 进度与主任务状态始终一致。
- 原有不带小任务的任务不受影响。
